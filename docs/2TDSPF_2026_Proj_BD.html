As falhas de negócio são convertidas por RAISE_APPLICATION_ERROR. Erros inesperados são propagados; não são transformados silenciosamente em sucesso, NULL ou score -1. O backend mostra mensagens de uso sem expor SQL ou credenciais.

Uma clínica existente sem atendimentos retorna []. Um ano sem movimento retorna total zero. Esses dois casos são resultados vazios válidos. Essa evolução em relação à Sprint 3 está documentada.

A auditoria usa valores OLD/NEW escalares e não consulta TB_PET no trigger. O teste transacional valida INSERT, UPDATE, DELETE e desfaz suas alterações ao terminar. Não há transação autônoma na auditoria.

JSON e modelagem MongoDB

O dataset oficial é produzido pela procedure, lendo as seis entidades relacionais. A versão salva deve ser exportada do Oracle real; dados de exemplo escritos manualmente não substituem o entregável.

atendimentos
  id_atendimento, data, status, valor
  clinica: { id, nome, cidade }
  veterinario: { id, nome, crmv, especialidade }
  servico: { id, descricao }
  pet: { id, nome, especie, raca, sexo, peso_kg }
  tutor: { id, nome }

Um documento representa um atendimento. Pet, tutor, clínica, veterinário e serviço ficam aninhados porque são consultados junto ao atendimento. Não se acumula um histórico ilimitado dentro do documento do pet.

O MongoDB representa uma projeção dos dados no momento da exportação. Alterar os documentos não atualiza o Oracle. Uma reimportação atualiza os IDs presentes no arquivo; documentos ausentes não são apagados automaticamente.

O importador preserva os campos originais, acrescentando data_bson (UTC) e valor_decimal (Decimal128). O arquivo JSON original não é alterado. O índice único em id_atendimento e o upsert impedem duplicação em reimportações.

O script compara todos os campos de cada documento importado com o arquivo, além da contagem. A coleção usa validação explícita e índices por pet/data e clínica/status/data.

O acesso Oracle é solicitado localmente, com senha oculta, ou lido do .env não versionado. O executor Java procura o driver JDBC que já acompanha as dependências do backend.

O instalador verifica a existência dos objetos desta versão e interrompe antes de sobrescrever um projeto existente. Não executa DROP nem modifica os objetos da Sprint 3. A instalação manual e o Flyway são alternativas: não misturar os históricos no mesmo schema.

O Oracle faz commits implícitos em DDL. Uma falha de instalação pode deixar objetos parcialmente criados; não há promessa de rollback completo do instalador. Corrigir a causa e revisar os objetos antes de repetir.

O MongoDB fica vinculado a 127.0.0.1, com volume persistente de demonstração. O comando parar mantém os dados. Não se utiliza --drop nem remoção automática de volumes.
